# macOS rejects the dev TLS cert, and run-dev.sh overwrites supplied certs

- Branch: devtls-276462d4
- Base: origin/develop @ 75ffbcc
- Queue owner: llm-knowledge-base session; this checklist owns this branch
  only.

- [x] Browsers on macOS reject wa's dev TLS certificate even when the user
      trusts it in Keychain.
    - Red test: `TestRunDevGeneratedDevCertificateMeetsMacOSServerRules`
      (`go test ./cmd/ -run` it) -> the generated cert has no
      basicConstraints, keyUsage, or extendedKeyUsage, and existing certs
      without them are reused.
    - Cause: `write_dev_tls_openssl_config` (`run-dev.sh`) set only
      `subjectAltName`, and the reuse check only looked at SANs. Apple
      requires extendedKeyUsage serverAuth and a validity of at most 398
      days (825 for user-trusted roots) on a trusted TLS server cert.
    - Fixed by adding `basicConstraints=critical,CA:FALSE`,
      `keyUsage=critical,digitalSignature,keyEncipherment`, and
      `extendedKeyUsage=serverAuth`, generating for 397 days, and
      regenerating a generated cert that lacks those extensions, has more
      than 397 days left, expires within 30 days, or no longer matches its
      key.
- [x] `run-dev.sh` regenerates in place any `WA_RESULTS_SERVER_CERT` /
      `WA_RESULTS_SERVER_KEY` that misses a SAN it collects, so a
      user-supplied or CA-issued cert is overwritten, and there is no way to
      give every mode (including the prod farm stack) a supplied cert
      without also changing the results CLI's trust root.
    - Red tests: `TestRunDevSuppliedDevCertificateIsNeverRewritten` and
      `TestRunDevProdServesDevCertificateFromEnvFile` -> a read-only cert
      fails regeneration, a writable one is rewritten, and `WA_TLS_CERT` set
      in `.env.production.local` is ignored.
    - Fixed by adding `WA_TLS_CERT` / `WA_TLS_KEY` (and `WA_TLS_CA_CERT` for
      a CA-signed cert), honoured in every mode for the results API, the
      `next dev` and prod HTTPS frontends, `WA_RESULTS_BACKEND_CA_CERT`, and
      the health probes. Only cert paths inside run-dev.sh's temp dir or the
      checkout's `.tmp` are ever (re)generated. A supplied cert is validated
      without writing: missing files, a key mismatch, expiry, or no
      `127.0.0.1` SAN stop startup; other missing SANs, near expiry, and no
      serverAuth only warn. DEVELOPING.md documents a personal cert and the
      farm stack setup; README.md points to it.
