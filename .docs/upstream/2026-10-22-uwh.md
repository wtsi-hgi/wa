# Unified Warehouse release, 2026-10-22

Announced for 22 October 2026 at 17:00; the date may slip. Assessed on
2026-10-21 against wa `develop` at `03ef638`.

Verdict: wa is compatible with both the old and the new schema. No wa
deployment is needed at the release time.

## Changes

| Change                        | Breaks sync | Wrong results | Compatible both ways |
| ----------------------------- | ----------- | ------------- | -------------------- |
| Study uuid shared across LIMS | No          | No            | Yes                  |
| New `useq_wafer` columns      | No          | No            | Yes                  |

### Study uuid shared across LIMS

The unique index on `study.uuid_study_lims` becomes unique on
`(uuid_study_lims, id_lims)`, so a Sapio study can share a uuid with a
Sequencescape study.

- Sync: the study source queries select named columns and keep only
  `id_lims = 'SQSCP'`, and `syncStudyTable` drops any other row again. Every
  source join to `study` carries the same filter. The cache keys `study_mirror`
  on `id_study_tmp` only, so a shared uuid cannot violate a cache constraint.
- Reads: every `study_mirror` read in `mlwh/*.go` filters on
  `id_lims = 'SQSCP'`, including uuid lookups (`ResolveStudy`,
  `ClassifyIdentifier`), faculty-sponsor study selection, the latest-data join,
  the iRODS identity join and the sample-CRAM export join. A Sapio row that
  shares the uuid and `id_study_lims` would otherwise change accessions,
  duplicate rows or resolve the uuid to the wrong study.

### New `useq_wafer` columns

`useq_wafer` gains nullable `application_type`, `uga_primer`, `ugb_primer`,
`converted_illumina_tag_sequence` and `converted_illumina_tag2_sequence`.

wa joins `useq_wafer` only for `id_useq_wafer_tmp`, `id_sample_tmp` and
`id_study_tmp`, in the Ultimagen product-metrics query and the iRODS recovery
query. The new columns are not selected. To use one later, select it only once
a probe finds it.

## Evidence

- `mlwh/upstream_schema_change_test.go`: a Sapio study sharing a SQSCP study's
  uuid and `id_study_lims` is excluded by sync from a source with the new
  unique index, and the reads above return only the SQSCP study, on SQLite and
  on a MySQL cache twin. A source `useq_wafer` with the new columns still syncs
  Ultimagen product metrics and iRODS locations. Removing any one read filter
  fails a test; removing the SQL and Go study sync filters together fails the
  sync test.
- `wa mlwh check-source` against the live MLWH on 2026-10-21 (old schema): all
  35 sync source queries prepared.
